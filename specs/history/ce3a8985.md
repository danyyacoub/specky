# Commit ce3a8985

- **Date:** 2026-09-17T10:53:14+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** refactor(document): give the refusal chain one owner

This commit refactors the document write path so the refusal logic has a single owner. The `lost_content` → `ungrounded_flags` → `unrenderable_mermaid` chain had been duplicated across both write paths, and adding the mermaid guard triplicated it; since that order is policy (losing prose is the worst outcome, mermaid is the only check that shells out to Node), leaving it in two places risked silent drift where both paths would still refuse but not the same things first. The chain now lives in `generator.doc_problem`, while `write()` sheds its five copy-pasted six-line refusal constructors and its two-regime `sources:` logic — the latter extracted into `_recorded_sources`, a self-contained answer to a self-contained question. Separately, `Toolbox` now builds its tools once instead of reconstructing seven tools and every schema literal per call; `invoke` had been doing that rebuild purely to resolve a name, so a sixteen-turn run paid for dozens of rebuilds and the provider's tool list was a different object graph from the one `invoke` resolved against.
