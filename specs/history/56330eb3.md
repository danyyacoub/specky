# Recent branch commits now share one history entry instead of one page each

- **Date:** 2026-09-25T10:17:44+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** feat(history): fold a branch's recent commits into one history entry

## What changed

Previously each commit produced its own generated history doc under specs/history/<sha>.md, so messages like "wip" and "fix typo" each created a page. Now a branch's recent commits fold into a single entry named for the branch (e.g. specs/history/feat-refund-limits.md), rewritten by each new commit to describe the whole change; on main/dev the entry is named for the first commit's subject. Entries accept new commits for 4 days after the first one ([history] window_days), only a branch's own first-parent commits fold in, and [history] consolidate = "off" restores one entry per commit. Doc-sync commits now carry a Specky-Documents trailer naming the commits they document.

## Why

One entry per commit made a page for every "wip" and "fix typo"; the branch-aggregated entry makes the history read as changes rather than steps.
