# Agents can now inspect what a feature is meant to do, on a cheaper model

- **Date:** 2026-09-22T17:38:04+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** feat: add find-feature skill and a [skills] model setting

## What changed

A new `find-feature` skill answers "what is this feature meant to do before I use it?" from the docs, returning the doc path and its behaviour ids (STEP-n, OUT-n, EDGE-n, AT-n) without reading source; `explore-docs` keeps the broader "how does X work?" and "why did it change?" questions. A new `[skills] model` setting in `specky.toml` (haiku, sonnet, opus; unset or `inherit` means the session model) decides what model the lookup and documentation skills run their work on, and `/specky:setup` now asks for it. Codex support was added alongside the existing Devin, Kiro and opencode integrations.

## Why

A model pinned in SKILL.md frontmatter couldn't be changed without forking the plugin, and in Claude Code it held for the rest of the turn; the new setting lets users choose the model their skills run on, and the lookup skills hand their work to a subagent so only the skill's own work moves off the session's model.
