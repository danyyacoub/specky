# Specky serve can now require a login to view a deployed site

- **Date:** 2026-09-23T18:00:35+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** feat(chat): require a login for specky serve from env credentials

## What changed

Previously `specky serve` left all pages and API routes open, with only the optional token guarding `/chat` and `/search`. Now, if `SPECKY_AUTH_USERNAME` and `SPECKY_AUTH_PASSWORD` are set in the server's environment, every route returns 401 with a browser login prompt until the correct credentials are supplied; setting only one of the two variables makes `specky serve` exit instead of starting.

## Why

A deployed viewer had no way to keep its docs private, since the token never guarded the pages. The credentials stay in the environment rather than in the committed `specky.toml`, so the password doesn't ship with the repo it protects.
