# Commit 271df786

- **Date:** 2026-09-12T23:02:55+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** Open the index in WAL mode so the hook and `specky serve` stop colliding

Index switched to WAL mode—readers and writers can coexist without the `database is locked` errors that plague default rollback journal. Under rollback journal, active reads block writes, causing silent hook failures or 500s from chat server. WAL mode keeps each reader's snapshot until its transaction ends, writers wait via `busy_timeout=5000` instead of failing immediately. Also set `synchronous=NORMAL` (safe under WAL; all tables are derived data `specky index` rebuilds). Tests confirm WAL is enabled and concurrent read/write succeeds.
