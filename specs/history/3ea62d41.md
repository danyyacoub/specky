# Commit 3ea62d41

- **Date:** 2026-09-22T10:08:09+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(viewer): point in-body doc links at rendered pages, not .md files

The commit message and diff describe a fix where in-body documentation cross-links were broken in the rendered viewer and exports. Docs link to each other using repo paths like `../cli/check.md`, but the rendered site serves flat `<slug>.html` pages, so every such link 404'd, and `#section` anchors had no matching heading ids to scroll to.

The fix introduces link rewriting that runs after body rendering: for the viewer, a resolver maps `.md` targets to the corresponding rendered page (via a new `page_name()` helper derived from the same `slug()` used to write pages, so links can't drift from the files `render_site` emits); for `specky export`'s single-page output, links resolve to the target doc's `<section>` anchor (with a per-doc prefix so duplicate heading names like "Edge Cases" don't collide), and headings get matching ids. Links naming files outside the output (e.g. excluded history docs) are unwrapped to plain text.

Two supporting details: `scroll-margin-top` was added to heading ids so `#section` links land below the fixed titlebar, and in the Spec Assistant answer path the same rewrite is applied *before* the sanitizer, so a percent-encoded `javascript:` href that the resolver decodes still gets caught by sanitization rather than slipping through as a live link.
