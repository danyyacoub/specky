# Cross-document links in rendered docs and export now take you to the right page or section

- **Date:** 2026-09-22T10:08:09+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(viewer): point in-body doc links at rendered pages, not .md files

## What changed

Links between docs that were written as repo paths (like `../cli/check.md`) used to 404 because the rendered site serves flat `<slug>.html` pages; now they resolve to the page the target doc was rendered to, and `#section` links land on the matching heading. In `specky export`, links point at the target's section within the single file, or drop to plain text if the doc wasn't included; Spec Assistant answers resolve such links the same way.

## Why

Docs link each other by repo path, but the site has no `.md` files or folders, so every cross-doc link 404'd and section links had no heading ids to land on. Link resolution also runs before the sanitizer so a decoded `javascript:` href is still caught.
