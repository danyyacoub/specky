# Provider failures now show the command's own error message, and doctor checks Devin login

- **Date:** 2026-09-24T11:10:20+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(ai): say why a provider command failed, and check devin cli login

## What changed

When an agent CLI provider command exits non-zero, the error reported to you now includes the command's printed reason (such as "Login canceled") instead of only an exit status. `specky doctor` also reports a failing config check when the `devin` provider is configured but the Devin CLI is not logged in, telling you to run `devin auth login`.

## Why

A failing agent CLI surfaced only "returned non-zero exit status 1", which hid the one line that explained it; and Devin CLI keeps its own login, separate from Devin Desktop's, so installed-but-logged-out was a common state that failed every call.
