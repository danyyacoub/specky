# Commit 95824de1

- **Date:** 2026-09-21T14:15:38+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(generator): keep an existing doc's type and tags across updates

Fixed a bug where every automatic doc update re-guessed and overwrote the doc's `type` and `tags`. Since the classifier only sees a commit's diff—never the doc's existing frontmatter—it kept flipping values (e.g. `specs/rendering/diagram-support.md` alternated feature/workflow/feature across commits), undoing hand corrections and sometimes demanding sections a doc never owed.

Now a model's classification only seeds a brand-new doc or fills in a missing `type`/`tags`; an existing doc keeps its own, and its type determines which sections it's asked for. The same rule applies to `specky document`, so re-running it can't revert a human correction either. Specs for the feature graph, `specky document`, classification, and sync were updated to document the new "set once, then preserved" behavior.
