# Specky MCP tools now find the project repo when the host starts them outside it

- **Date:** 2026-09-24T11:03:17+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(mcp): find the repo per call when the host starts the server elsewhere

## What changed

Previously every MCP tool except ping failed with a generic error when the host launched the server from a directory that wasn't the project, such as the home directory Devin Desktop uses. Tools now resolve the repository per call: first SPECKY_REPO_ROOT, then the current directory, then the workspace folders the host reports; when none is a git repo they return a clear error naming SPECKY_REPO_ROOT and what to set.

## Why

Devin Desktop starts MCP servers from the user's home directory, so git rev-parse found no repo and all tools but ping failed; the repo is now resolved per call because one server process can outlive a workspace switch.
