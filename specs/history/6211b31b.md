# Re-running init keeps your other specky.toml settings

- **Date:** 2026-09-22T17:37:39+02:00
- **Author:** dany <dany.yacoub@gmail.com>
- **Message:** fix(cli): keep other specky.toml tables when init rewrites it

## What changed

Running `specky init` on an existing `specky.toml` now rewrites only the `[ai]` and `[docs]` tables, leaving every other table such as `[serve]` and `[skills]` exactly as written, comments included, and prints a line naming what it kept. `[docs]` is now always written, recording `root = "specs"` when the default is used. If the existing file isn't valid TOML, `init` stops and names the file before asking any question or calling the provider, leaving the file untouched.

## Why

`init` owns the provider and docs root, but the viewer's port and the skills' model belong to whoever set them, and switching provider mustn't quietly take them along. With no parse there's no telling which tables to keep, and overwriting would lose them silently.
