# AGENTS.md

**Read [CLAUDE.md](CLAUDE.md) first.** It's this repo's instruction file — what specky is, every CLI
command, the scripts, and the architecture notes that say which module owns what. It applies to any
agent, not only Claude Code; it's just named for the tool that reads it automatically.

This file exists because agents that follow the [AGENTS.md](https://agents.md) convention (Devin,
among others) don't read `CLAUDE.md`. Everything specific to those hosts lives in
[integrations/](integrations/) — [Devin](integrations/devin/README.md),
[Kiro](integrations/kiro/README.md), [opencode](integrations/opencode/README.md). Rather than
duplicate CLAUDE.md here and let the two drift, this is a pointer plus the handful of things that
only bite an agent working in a fresh checkout.

## Setup

```bash
uv sync --all-groups      # this repo runs its own working copy
scripts/test.sh           # the test suite; run it before you claim a change works
```

There's no build or lint step. `specky` isn't on PATH in a fresh checkout — run it as
`uv run specky <command>`.

Some commands need an AI provider, which needs `specky.toml` (gitignored, so a fresh checkout has
none) and an API key in the environment. Everything on the read side — `index`, `search`, `check`,
`pr-comment`, `render-html`, `tests`, `export`, `doctor` — is offline and needs neither. If you have
no key, stay on that side; don't invent a config.

## This repo documents itself

`specs/` is specky's own functional documentation, generated by running specky on this codebase. So
a change to specky's behaviour is also a change to the docs describing it, and the same rule this
repo asks of its users applies here:

- Docs are `specs/<domain>/<topic>.md` — kebab-case topic, never `README.md`. `specs/MODULES.md`
  indexes them; `specs/GLOSSARY.md` is the shared vocabulary.
- Never hand-write or edit anything under `specs/history/`. One generated micro-doc per commit.
- Before opening a pull request: `uv run specky index && uv run specky check --base origin/main`.
  Offline, free, and it names the doc a change left stale while you can still fix it.
- The installed git hooks document commits automatically. A `docs: sync specky docs [skip specky]`
  commit appearing after yours is expected — leave it alone. Set `SPECKY_DISABLE_HOOK=1` if you need
  the hook to stay out of the way.

## Conventions worth knowing before you edit

- Never hardcode `specs`. [`src/specky/paths.py`](src/specky/paths.py) is the only place the docs
  root is spelled out, because a repo can rename it via `[docs] root`.
- Every FTS5 `MATCH` query goes through `db.fts_match_query()` — a raw user string in a `MATCH` is a
  syntax error waiting to happen ([specs/search/fts5-syntax-safety.md](specs/search/fts5-syntax-safety.md)).
- The comments in this codebase explain *why*, at length, and that's deliberate. Match the density of
  the file you're editing rather than stripping it to match your own habits.
